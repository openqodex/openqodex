`run` passes `{ [GET]: fn, put }` to `load(store: Store)`. The key `[GET]` is computed, so the graph cannot read its name, and the object may have `get`. A graph that records only the keys it can read, and does not mark the object as open, finds no object with `get` and `put` and drops the `unsupported-rule` gap on `store.get`. The call must keep it, beside the possible edge to `MemStore.get`. `Lone` is the negative control: the computed key of `half` holds a string, which never runs code, and `half` has no `save`, so `l.find` leaves no gap.
