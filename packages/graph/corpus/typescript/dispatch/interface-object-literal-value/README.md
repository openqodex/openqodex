`run` passes an object literal written in place, `{ get, put }`, to `load(store: Store)`, and `build` returns an object literal that is a `Maker`. Neither object is a definition of the graph, so a call through `Store` or `Maker` may run code no listed target holds. `MemStore` matches `Store` by shape and is listed, and the change edits `MemStore.get`. A graph that drops the `unsupported-rule` gap once it has listed the classes of that shape tells the reviewer the list of what `store.get` may run is whole, when the inline object's `get` is missing from it. Both calls must keep the gap, beside the possible edge to `MemStore.get`, whose note says its methods matched by name. `Lone` is the negative control: the only object literal with `find` has no `save`, so it can never be a `Lone`, and `l.find` leaves no gap.
