`run` makes a function `f` and gives it `get` and `put` by assignment, then passes it to `load(store: Store)`. `wrap` builds a `Cache` with `Object.assign(fn, { read }, { write })`. Neither value is a definition of the graph, so a call through `Store` or `Cache` may run code no listed target holds. `MemStore` matches `Store` by shape and is listed, and the change edits `MemStore.get`. A graph that drops the `unsupported-rule` gap once it has listed the classes of that shape tells the reviewer the list of what `store.get` may run is whole, when the `get` assigned to `f` is missing from it. Both calls must keep the gap, beside the possible edge to `MemStore.get`. `Lone` is the negative control: `half` is given `find` and a string `label`, never `save`, so it can never be a `Lone`, and `l.find` leaves no gap.
