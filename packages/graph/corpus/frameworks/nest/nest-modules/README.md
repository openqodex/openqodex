Two Nest applications in one project. The main one (src/main.ts) sets the global prefix from a constant, excludes `health` from it, and turns on URI versioning with default version 1; its root module imports a pets module, a cats module and a dogs module placed under `pets` and `pets/cats` by `RouterModule.register` (the dogs module as a bare child), and a shared module through `forwardRef`. The cats controller has a method with `@Version("2")`; the dogs controller declares versions 1 and `VERSION_NEUTRAL`. The admin application (src/admin-main.ts) has no prefix and no versioning and imports the same shared module. The change edits the shared controller. A reader that joined paths by hand, ignored the module paths, the version or the exclusion, or merged the two applications, would list a path the server does not answer. The case checks every composed path against what Nest's own path factory makes, that the health route keeps its version but loses the prefix, that the dogs route is listed once per version, and that the shared route is listed once for each application with its own path.
