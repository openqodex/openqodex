Fewer caller lists of TypeScript and JavaScript functions say "list incomplete" when nothing can reach the function unseen. A callback elsewhere in the package no longer marks every function's list incomplete. The list stays a floor, with a reason that names the place, when the function is used as a value (passed, stored, picked by a ternary, bound), when its module is passed on or indexed (through any chain of `export *`), when code is built at run time (`eval`, `new Function`), or when a module may be loaded by a computed path. A file the reader cannot vouch for (a free global name, `this` outside a class, `import.meta`) keeps a floor on what it defines and imports; one that may load any module (code made from a string, the global object indexed) keeps a floor on every function. A timer given a function it can prove (a local function never given another value, a function-typed parameter, a Promise's `resolve`) and a build-time constant its project declares as a string, number or boolean no longer keep a floor. The reason names up to three such files with their lines and what each does. A graph kept by an older version is built again.
