A caller list that is a floor now says where a missing caller could be. When every place that could hide one is a test, fixture, corpus, benchmark or top-level script file, `unknown.scope` is `tests` and `unknown.note` says so in one sentence, naming up to three of those places: `Complete in product code. Only test, benchmark or script files could hide a caller: ...`. The command line prints that sentence after `floor:`. Any other floor has `scope` `all` and keeps its reasons as before. The list stays a floor in both cases. A read of a parameter or local named `require` no longer counts as loading a module by a computed path, unless `createRequire` made it. `import.meta.url`, `import.meta.dirname`, `import.meta.filename`, `performance.now`, `Atomics.wait` and `process.cpuUsage` no longer make a file one the reader cannot vouch for. Scripts under `packages/<name>/scripts/` count as outside product code too. A function passed as a value, from a test too, keeps the scope `all`, as do code built at run time, a module loaded by a computed path, a file not read and any callers answer more than one hop deep. A getter read by a bracket key (`c["total"]`, `c[k]`) or taken apart by a pattern (`const { total } = c`) keeps its floor. `createRequire` reached through an alias (imported above or below its use), a namespace, a default import, `require("module")`, a bracket key or a re-export, and a local `require` made by any call, still load a module by a computed path. A method named `createRequire` on any other value loads nothing. `new.target` and `queueMicrotask` no longer make a file one the reader cannot vouch for.
