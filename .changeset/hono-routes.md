"openqodex": minor
---

The code graph now reads Hono applications, including `@hono/zod-openapi`. `openqodex graph routes` lists every route a Hono app serves with its method, its full path, its handler and the application that serves it, instead of answering that Hono is not read. Routes registered with `openapi()` and a `createRoute` constant from another file are listed, routers that a factory function builds and a wrapper such as `withAuth(router, middleware)` returns are composed under their `route()` prefix, and an OpenAPI `{id}` is shown as `:id`, as Hono serves it. Two apps in one repository keep their routes apart. A part the graph cannot follow, such as a router a function returns from two places or an inline handler, is reported as an unknown at its line instead of a guessed path. A `use()` whose first argument may be a path computed at run time, such as `app.use(process.env.AUTH_PATH, auth)`, no longer applies its middleware to every route: which routes it covers is reported as unknown. A router factory written on one line, such as `() => new Hono().get("/", (c) => c.json(x))`, is followed into: the inline handler's return is no longer taken for a second return of the factory. A wrapper or a named handler in a file that imports nothing of Hono is followed and bound too. A route registered with no path, such as `app.get(handler)` or `.post(handler)` chained after `get("/x", h)`, is reported as an unknown instead of being dropped without a word. A router or a `createRoute` constant exported through an export clause (`const app = new Hono(); export { app }`, or `export { app as api }`) and imported elsewhere is followed to its mount, instead of being listed as an application of its own at its relative path.
