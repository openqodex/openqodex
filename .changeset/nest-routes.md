The code graph now reads Nest applications. `openqodex graph routes` lists every route a Nest app serves with its method, its full path, the controller method that handles it and the application that serves it, instead of answering that no framework is read. Paths are composed the way Nest composes them: the global prefix and its exclusions, URI versions, `RouterModule` paths, the controller's path and the method's path. A controller counts for an application only when a module its root module imports declares it. A part the graph cannot read, such as a prefix computed at run time, leaves the route with no path and says why, rather than guessing a path the server does not answer. Guards and interceptors are listed as each route's middleware. A global prefix set under a condition or a loop written without braces, or behind `&&`, is not applied as certain. A `RouterModule` table past the plugin's cap marks every module's path unknown instead of dropping later entries. A route path holding a query (`/items?token=x`) is not kept and not listed, so no query value is copied into the graph's cache. JavaScript escapes in a path, such as `\u002f`, are decoded as the language decodes them. A `NestFactory` that a function parameter shadows makes no application.
