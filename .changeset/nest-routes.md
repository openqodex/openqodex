---
"openqodex": minor
---

The code graph now reads Nest applications. `openqodex graph routes` lists every route a Nest app serves with its method, its full path, the controller method that handles it and the application that serves it, instead of answering that no framework is read. Paths are composed the way Nest composes them: the global prefix and its exclusions, URI versions, `RouterModule` paths, the controller's path and the method's path. A controller counts for an application only when a module its root module imports declares it. A part the graph cannot read, such as a prefix computed at run time, leaves the route with no path and says why, rather than guessing a path the server does not answer. Guards and interceptors are listed as each route's middleware. A global prefix set under a condition or a loop written without braces, or behind `&&`, is not applied as certain. A `RouterModule` table past the plugin's cap marks every module's path unknown instead of dropping later entries. A route path holding a query (`/items?token=x`) is not kept and not listed, so no query value is copied into the graph's cache. JavaScript escapes in a path, such as `\u002f`, are decoded as the language decodes them. A `NestFactory` that a function parameter shadows makes no application. A path constant that names another constant of its file (`const P = BASE`) is read wherever `BASE` is declared, up to four such steps, in time that grows only with the file, and a constant exported through `export { P }` is read in the file that imports it. The count of guard and interceptor edges left out past the plugin's budget now counts every edge, not one per route. A comment between a route decorator and its method no longer drops the route. A controller that extends a guarded base class and adds guards of its own now lists both: the base class's guards and interceptors first, then its own, as Nest merges them, also through a base class with no decorators. A file of many controllers is now read in time that grows with the file: each route's handler was looked up by scanning every symbol of its file, which made the cost grow with the file's routes times its symbols.
